# 05. 生成并丰富 LinkedIn 潜在客户

## ⚙️ 此工作流的工作原理

工作流分为几个关键步骤，每一步都旨在帮助你构建和丰富一份有价值的 LinkedIn Leads 列表：

### 1. 🔑 线索发现（通过 Apollo 的关键字搜索）

- 通过 Apollo.io 的 API，根据关键字、行业或职位提取线索。
- 将线索姓名、职位、公司和 LinkedIn URL 保存到 Google Sheet。
- 你可以将表单节点替换为 webhook、whatsapp、telegram 等触发节点，通过任何方式发送查询变量来启动工作流。

### 2. 🧠 用户名提取（从 LinkedIn URL）

- 通过一个简单的脚本节点从个人资料 URL 中提取 LinkedIn username。
- 这是通过 RapidAPI 进一步丰富数据的必要步骤。

### 3. ✉️ 邮箱查找（通过 Apollo User ID）

- 使用 Apollo User ID 获取线索的已验证工作邮箱（verified work email）。
- 确保高线索质量，拥有可靠的联系方式。
- 为了双重确认邮箱当前有效，我们使用 mail.so API，过滤掉无法投递和 mx-record 检查失败的邮箱。我们不想冒险发送邮件到不再存在的地址，对吧？

### 4. 🧾 个人资料摘要丰富（通过 RapidAPI）

- 查询 LinkedIn Data API 以获取线索的个人资料摘要/bio。
- 帮助你更深入地了解他们的背景和专业知识。

### 5. 📰 近期活动收集（帖子与转发）

- 从每个线索的个人资料中获取最近的帖子或转发（posts or reposts）。
- 非常适合根据他们目前正在谈论的内容定制外联消息。

### 6. 🗂️ 线索数据库更新

- 所有丰富的数据写入同一个 Google Sheet。
- 填充新列，同时不覆盖现有数据。

### ✅ 智能重试与行状态逻辑

每个子工作流都包含一个故障安全机制（fail-safe mechanism）以确保：

- ✅ 每一行都有状态列（如 done、failed、pending）。
- 🕒 一个定时重试工作流（scheduled retry workflow）在 2 周后（可自定义）将失败的行重置为 pending。
- 💬 这为失败的丰富处理提供了再次被处理的机会，减少数据丢失。

## 🔐 所需的 API Keys

使用此工作流需要以下凭据：

**🧩 Apollo.io**
- 在此注册并获取密钥：Apollo.io API Keys
- ⚠️ **重要提示：** 生成密钥时请切换 "Master API Key" 选项为 ON。
- 这确保同一个密钥可以在本工作流中使用所有 Apollo 端点。

**🌐 RapidAPI（LinkedIn Data API）**
- 在此订阅 API：LinkedIn Data API on RapidAPI
- 在相应节点的 x-rapidapi-key 头部中使用该密钥。

**✉️ Mail.so**
- 在此注册并获取密钥：Mail.so API

**💡** 对于这两个 API，在 n8n 中将凭据设置为 "Generic Credential" 类型。
这样就不需要在每个节点中重新配置头部。

## 🛠️ 自定义选项

- 修改 Apollo 过滤器（位置、行业、资历）以定位你理想的客户。
- 更改调度程序中的重试间隔（例如每周而不是 2 周）。
- 将数据库连接到你的电子邮件营销工具，如 Mailchimp 或 Instantly.ai。
- 用你期望的 AI agents 替换 AI 节点，并进一步自定义 system messages 以获得预期结果。
