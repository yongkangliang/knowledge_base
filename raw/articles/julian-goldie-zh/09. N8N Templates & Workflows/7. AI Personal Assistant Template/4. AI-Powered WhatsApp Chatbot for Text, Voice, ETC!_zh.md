# 4. AI 驱动的 WhatsApp 聊天机器人：支持文本、语音等

此模板专为技术公司的内部支持团队、产品专家和知识管理员设计，旨在自动化产品文档的导入，并通过 WhatsApp 实现基于 AI 的检索增强型问答。

**此工作流解决了什么问题？**

支持代理经常花费过多时间手动搜索冗长的文档，导致答案不一致或延迟。此方案自动化导入、拆分和索引产品手册，然后利用检索增强生成（RAG）通过 WhatsApp 消息，以 AI 准确快速地回答用户查询。

**这些工作流的功能**

**工作流 1：文档导入与索引**

手动触发，从 Google Docs 导入产品文档。

自动将大文档拆分为块，以便高效搜索。

使用 OpenAI 嵌入为每个块生成向量嵌入。

将嵌入的块和元数据插入 MongoDB Atlas 向量存储，实现快速语义搜索。

**工作流 2：AI 驱动的 WhatsApp 查询与响应**

监听传入的 WhatsApp 用户消息，支持多种类型：

文本消息：用户的纯文本查询。

音频消息：语音笔记转录为文本后进行处理的文字。

图片消息：照片或截图分析以提供上下文答案。

文档消息：解析 PDF、电子表格或其他相关文件。

将传入的查询转换为向量嵌入，并在 MongoDB 向量存储上进行相似度搜索。

使用 OpenAI 的 GPT-4o-mini 模型配合检索增强生成，生成简洁且具有上下文感知能力的答案。

使用 memory buffer node 跨多轮对话保持上下文。

将不同类型的消息路由到相应的处理 node，以最大化答案质量。

**设置**

**设置向量嵌入**

认证 Google Docs 并连接包含你想索引的产品文档的 Google Docs URL。

认证 MongoDB Atlas 并连接你要存储向量嵌入的集合。为此集合创建搜索索引以支持向量相似性查询。

确保索引名称与 n8n 中配置的一致（data_index）。

参考下面的示例 MongoDB 搜索索引模板。

**设置聊天**

使用你的 Meta 账户凭据对 WhatsApp node 进行身份认证，以启用消息接收和发送。

将包含嵌入产品文档的 MongoDB 集合连接到用于相似性查询的 MongoDB Vector Search node。

在 Knowledge Base Agent node 中设置系统提示词，以反映你公司的语气、回答风格以及任何业务规则，确保它引用已连接的 MongoDB 集合来获取上下文。

**确保**

两个 MongoDB node（在导入和聊天工作流中）都连接到同一个集合，包括：

一个存储向量数据的 embedding 字段，

相关元数据字段（例如文档 ID、来源），

并且配置了相同的向量索引名称（例如 data_index）。

搜索索引示例：

{
"mappings": {
"dynamic": false,
"fields": {
"_id": { "type": "string" },
"text": { "type": "string" },
"embedding": {
"type": "knnVector",
"dimensions": 1536,
"similarity": "cosine"
},
"source": { "type": "string" },
"doc_id": { "type": "string" }
}
}
}
